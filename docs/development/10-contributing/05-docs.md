# 文档规范

## 1. 目录与命名

- 目录按读者任务分层（见 [README](../README.md)），编号两位数字。
- 文件名小写连字符：`03-service-call.md`。
- 每篇开头给出：适用分支、读者、关联文档（表格或引用块）。
- 新增文档必须在 `docs/development/README.md` 与根 `README.md` §10 登记。

## 2. 内容要求

| 类型 | 要求 |
|------|------|
| 快速上手 | 可复制运行、零外部依赖、只有一条路径 |
| 概念 | 解释「为什么」，不写操作步骤 |
| 开发指南 | 按任务组织，每节可独立执行 |
| 配置 | 区分「语义解释」（04）与「键表」（08） |
| 参考 | 只写事实：签名、字段、默认值、约束 |
| Runbook | 按症状组织：现象 → 原因 → 确认 → 处置 |

## 3. 代码示例

- 必须能编译；无法完整运行时给出必要上下文（假设的前置条件）。
- 使用 `github.com/maczh/mgin`（jh 线），不要出现 `/v2`。
- 避免伪代码；`// ...` 只用于省略非关键部分，且要说明。
- 示例中的配置与代码保持一致（键名、端口、路径）。

## 4. 链接与锚点

- 站内链接使用相对路径，不写仓库绝对 URL。
- 锚点规则：GitHub 会把标题转小写、空格转 `-`、去掉标点；中文保留。
  `## 7. 常见问题` → `#7-常见问题`。
- 修改标题后必须全仓搜索旧锚点并修复。
- 合并前用脚本检查链接目标是否存在（见 §6）。

## 5. 术语与语气

- 统一使用 [术语表](../11-appendix/02-glossary.md)：组件、子配置、门面、执行器、探针、接口日志。
- 用肯定句描述行为；未实现的能力必须显式写「未实现」。
- 不写「应该」「可能」「大概」；不确定就注明「未实测」。
- 中英文之间加空格；代码、键名、路径用反引号。
- 不使用表情符号。

## 6. 自检脚本

```bash
# 1. 链接目标是否存在（相对路径）
python3 - <<'EOF'
import pathlib, re, sys
root = pathlib.Path("docs/development")
bad = []
for p in root.rglob("*.md"):
    for m in re.finditer(r"\]\((?!https?://|#)([^)#]+)", p.read_text(encoding="utf-8")):
        target = (p.parent / m.group(1)).resolve()
        if not target.exists():
            bad.append(f"{p}: {m.group(1)}")
print("\n".join(bad) if bad else "links ok")
sys.exit(1 if bad else 0)
EOF

# 2. 标题层级与空行（示例）
grep -rn "TODO\|TBD\|待补充" docs/development
```

## 7. 版本与时效

- 文档不单独打版本号；以代码分支 + tag 为准，在页首注明基线。
- 代码行为变更时，同一次 PR 更新文档；不接受「下个 PR 再补」。
- 历史长文（`README_CN.md`/`README_en.md`）不再扩写；如发现错误，优先修正 `docs/development` 并在长文顶部提示。
