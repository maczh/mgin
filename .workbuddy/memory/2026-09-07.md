## MGIN 安全审计（client / db / registry 目录）

对 `client/`、`db/`、`registry/` 三个目录做了空指针/越界/类型断言隐患审计与修复，全项目 `go build ./...` 与 `go vet` 均通过。

主要修复点：
- **client/client.go**：`CallT` 的 `resp[:1]` 空串越界；`getHostFromCache` 的 `h.(string)` 未做 ok 断言 + `cache.OnGetCache` 返回 nil 保护。
- **db/dao**：`clickhouse.go` 的 `MultiCreate` 误用 `db.Mysql.GetConnection`（应为 Clickhouse）；三个 DAO 的 `Exists` 用 nil `*E` 调用 `First` 导致永远返回 false（改为值类型 `&result`）；三个 DAO 的 `Pager` 对传入 `conn` 加 nil 保护（避免 `Where` 连接失败返回 nil 后链式 panic）。
- **db/mysql|postgres|clickhouse**：`xxx.DB()` 返回 nil 未判空就调 `Ping`/`Close`/`Set*`（Init/Close/Check 全部加 `err==nil && db!=nil` 保护）；`mysql.RedisCacher` 对 `c.Rdb` 加 nil 保护。
- **db/sqlite**：`dbFileName[1:2]` 单字符文件名越界；`Close` 的 `DB()` 返回 nil 保护。
- **db/kafka**：`client.Brokers()[0]` 空列表越界；`Close`/`Check`/`GetProducer` 等系列方法对 `k.client` 加 nil 保护。
- **db/es/escrud.go**：`doc["id"].(string)` 类型断言；`AddDocuments` 空 `docs` 时 `docs[0]` 越界；`buildMappings` 中 `v.([]any)[0]` 空数组越界（均已修复/id 归一化）。
- **registry/consul**：`ports[i]` 索引越界、`consul_urls[0]` 空地址越界、`localip[0]` 越界、`groupName[0]` 越界、`service.Service.Tags[2]` 越界、`c.client` nil 保护。
- **registry/etcd**：同上 `ports[i]`/`localip[0]`/`groupName[0]`/`kv.Key[len(prefix):]` 越界、`c.client` nil 保护。
- **registry/nacos**：`localip[0]` 越界；`DeRegister` 的 `n.worker` nil 保护。
- **registry/polaris**：`localip[0]` 越界；`res1.Responses[0]` 空响应越界；`serviceId.(string)` 未做 ok 断言。

## 修复“无法获取配置文件时 panic”（config 根因）
- **根因**：`config/configure.go` 的 `GetConfigData` 在 etcd 分支直接 `return resp.Kvs[0].Value`，当配置键不存在（`len(resp.Kvs)==0`）时 `index out of range [0] with length 0`，导致 `mgin.Init` 连接 MySQL 等时 panic。
- **修复**：
  - `config/configure.go`：etcd 分支增加 `len(resp.Kvs)==0` 判断，记录错误日志并返回 `nil`，不再 panic。
  - `db` 各 `Init`（redis/mongo/kafka/es 原仅判 `!=nil`，现统一为 `==nil || len==0` 时记录错误日志并 `return`），与 mysql/postgres/clickhouse 行为一致；缺失配置时清晰报错而非静默加载空配置。
  - `registry` 各 `Register`（nacos/etcd/consul/polaris）入口增加 `==nil || len==0` 保护，缺失配置时记录错误日志并 `return`。
- 验证：`go build ./...` 与 `go vet ./config/... ./db/... ./registry/...` 均通过。
- 注意：`mgin.Init` 中对各 db/registry 的直接 `Init/Register` 调用（mgin.go:71 等）未做 nil 前置检查（与 `Use` 路径不一致），但因上述 Init/Register 已自保护，不会 panic；如需与 `Use` 一致地跳过，可在调用前 nil 判断。
