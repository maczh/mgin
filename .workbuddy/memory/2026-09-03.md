# 2026-09-03

## 新增 cmd/ 脚手架命令行工具（模仿 beego bee）
- 入口：`cmd/mgin.go`（`new` / `version` / `help`）。
- `cmd/new.go`：解析 `mgin new <工程名> [选项]`，支持交互式与 flag；处理位置参数与 flag 混排。
- `cmd/templates.go`：代码/配置模板（main/router/controller/model/dao/service/go.mod 等）。
- `cmd/scaffold.go`：推导配置并写出工程树。
- 关键坑：Go `flag.Parse` 遇到第一个非 flag 位置参数会停止解析，故 `mgin new <name> --flags` 需先抽出首个位置参数再解析其余。
- 生成工程已实测：`go build` 通过；运行时正确监听端口、注册路由、挂载 JWT/Casbin 中间件、controller→service→dao 调用链通畅。
- 生成的 `go.mod` 默认 `require github.com/maczh/mgin v1.25.7`，使用者需按实际发布版本调整并 `go mod tidy`。

## cmd/ 脚手架第三轮：go.mod 的 mgin 版本改为自动获取最新发布版
- `tmplGoMod` 中硬编码的 `v1.25.13-jh` 改为模板变量 `{{.MginVersion}}`；`ProjectOptions` 新增 `MginVersion` 字段。
- `new.go` 新增 `resolveMginVersion()`：读取 `GOPROXY` 第一个代理（忽略 direct/off，缺省 proxy.golang.org），GET `<proxy>/github.com/maczh/mgin/@v/list`，用 `golang.org/x/mod/semver` 取最高版本；网络失败/超时（context 10s）回退 `defaultMginVersion = "v1.25.13-jh"`。
  - 关键点：不能用 `@latest`，因为 `-jh` 是 semver 预发布号，`@latest` 会返回较低的非预发布版（如 v1.25.4）；必须拉全量列表取 max。
- 新增 `--mgin-version <ver>` flag，可手动指定覆盖自动获取（离线/指定版本场景）。
- `go.mod` 将 `golang.org/x/mod` 由 indirect 提升为 direct 依赖（已是 v0.25.0）。
- 实测：联网生成 go.mod 自动写入 `github.com/maczh/mgin v1.25.13-jh`；离线（不可达代理）回退同一默认版本，均正常。
- 注意：本环境 Bash 的 stdin 是 pty，`isTerminal` 恒为 true → `mgin new` 会进入交互菜单而阻塞；非交互测试需 `echo "" | ./mgin new ...` 将 stdin 变为管道。

## cmd/ 脚手架第四轮：消息队列改为多选 + 官方插件
- `MQ` 字段由 `string` 改为 `[]string`；`--mq` 支持 `nats,kafka,mqtt,rabbit` 逗号分隔多选；交互菜单改用 `askMulti`（选项含 `none`，选它/直接回车 = 不使用）。
- 新增 `mqPlugins` 映射（templates.go）：nats→github.com/maczh/nats(nats.NATS, v0.0.2)；kafka→github.com/maczh/mgkafka(mgkafka.Kafka, v1.1.2)；mqtt→github.com/maczh/mqtt(mqtt.MQTT, v1.1.6)；rabbit→github.com/maczh/mgrabbit(mgrabbit.Rabbit, v0.1.1)。四者均实现 `Init([]byte)/Close()/Check() error`，与 mgin 的 `dbInitFunc/dbCloseFunc/dbCheckFunc` 签名吻合。
- 新增 `mqOrder` 固定输出顺序（nats,kafka,mqtt,rabbit），保证 go.mod/plugins.go 生成稳定。
- 生成 `plugins.go`：模板 `tmplPlugins`，按 `app.MGin.Use("组件名", pkg.Singleton.Init, pkg.Singleton.Close, nil)` 逐个注册；`tmplMain` 在 `.HasMQ` 时调用 `registerMQPlugins(app)`。注意 `MGin` 是 `*App` 的导出字段（类型 `*mgin`），不是包级变量，故必须用 `app.MGin.Use(...)`。
- 配置键实测确认：nats=`go.data.nats.{multi,uri,user,password}`；kafka=`go.data.kafka.{servers,ack,auto_commit,partitioner,version}`；mqtt=`go.data.mqtt.{multi,broker,clientId,username,password}`；rabbit=`go.rabbitmq.{multi,uri,exchange}`。组件前缀映射：nats/kafka/mqtt 同名，rabbit→`rabbitmq`（即 `go.config.prefix.rabbit: rabbitmq`，文件 `rabbitmq-test.yml`），但 `Use()` 的组件名仍用 `rabbit`（须与 `go.config.used` 中的键一致）。
- **kafka 冲突点**：mgin 内置 sarama 版 kafka（mgin.go `if strings.Contains(used,"kafka")`），used 含 kafka 时内置客户端会先初始化，再初始化 mgkafka 插件，两者读同一份配置。任何含 "kafka" 子串的键都躲不开该判断，故沿用 `kafka` 键并在生成代码注释中说明。
- 修复：`splitArgs` 的 `valueFlags` 漏了 `-mgin-version`，导致其取值被当成位置参数（工程名）。
- 实测：`--mq nats,kafka,mqtt,rabbit` 生成工程 `go mod tidy` + `go build` 全通过；单选与不选场景亦正确（不选时不生成 plugins.go）。
