- 调研方式：三个并行 Explore 子 agent 分别啃 mgin 框架本体、github.com/maczh 下 9 个插件仓库、jihaihotpot.com/jihai 下 16 个业务项目。
- **重大发现（此前未记录）**：mgin 仓库本地有 `v2` 分支（module `github.com/maczh/mgin/v2`，包路径 `pkg/xxx`），当前工作树在 `jh` 分支（v1）。`jh-ris-booking` 用的是 v2，其余 jh-ris-* 用 v1。两套 API 不兼容：包路径、路由注册签名、DAO 实例化值/指针、插件契约都不同。
- 其他关键事实：
  - 9 个插件（mgkafka/mqtt/nats/mgrabbit/mssql/opensearch/hbase/hive/influxdb）**都不 require mgin**，靠「实现 Init/Close/Check 三方法 + 解析 `go.data.<name>.*`」的约定对接。mgrabbit 配置节点是 `go.rabbitmq.*`（唯一没有 data 层）。
  - 业务项目**不 import 框架的 `models.Result`**，而是每个项目复制一份 `vo.Response[T]{Code,Data,Msg,SrvTime}`。
  - 官方脚手架在 `mgin/cmd`（独立 module，`github.com/maczh/mgin/cmd/mgin`），`mgin new` 生成骨架；jh-ris-booking 就是它生成的。
  - 框架 README / sdk_document.md 有多处与代码不符（db.Pg、db.Kafka、mgin.MGin 全局变量、mgin.Default() 都不存在），已写入 pitfalls。

### §4 utils 缺陷（jh 工作树 + v2 worktree `mgin-v2-fix`）
- **linklist**：`Get` 越界返回零值+`TryGet`；`Remove` 越界空操作；v2 额外修 `Remove(1)` 空指针、`Add/Pop` 无锁读 size、`next.next.prev` 空指针、`Dequeue`→`dequeueLocked`（`-race` 压测通过）。
- **expire_cache**：两分支改全程持 `c.mu`，`mp.Range` 在锁内仅 `Delete(key)` 避免自锁（`-race` 0 WARNING）。
- **sqlvalidate**：v2 `index>0`→`index>=0`（首字符漏判）；jh 已在 `6cd633b` 修。死关键字（table 等）刻意保留。
- **sftp**：保留 `SftpConnect`（标 MITM 风险），新增 `SftpConnectWithHostKey`/`WithKnownHosts`；v2 修 `SftpClose(nil,nil)` 崩溃。
- **iputil**：保留 `IsPortUse`（两分支语义相反，各自标注），新增 `IsPortAvailable`。
- 另更新 README_CN/README_en/sdk_document 失效描述 + 4 个新 API。
